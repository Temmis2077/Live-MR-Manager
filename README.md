# 🌊 OSW — Open Stem Wave

> **개방형 스템 분리 미니 DAW.** 곡을 스템(보컬·반주, 곧 악기별)으로 열어, 그 위에서
> 노래하고 연습하고 다시 믹싱합니다. 노래 방송 스트리머를 우선으로, 커버 제작·연습까지.

[![Tauri 2.0](https://img.shields.io/badge/Tauri_2.0-FFC131?style=for-the-badge&logo=tauri&logoColor=white)](https://tauri.app/)
[![Rust](https://img.shields.io/badge/Rust-000000?style=for-the-badge&logo=rust&logoColor=white)](https://www.rust-lang.org/)
[![ONNX Runtime](https://img.shields.io/badge/ONNX_Runtime-005BA1?style=for-the-badge&logo=onnx&logoColor=white)](https://onnxruntime.ai/)

**OSW(Open Stem Wave)** 는 로컬에서 도는 AI 음원 분리·오디오 제어 데스크톱 앱입니다.
유튜브/로컬 곡을 AI로 **보컬·MR 스템으로 분리**하고, **가사를 자동으로 싱크**하고, OBS
오버레이로 방송에 얹습니다. 여기에 내부 이펙트·마이크 입력·라우팅을 더해 **작은 DAW**로
자라나는 것을 지향합니다.

> ### 원본과의 관계
>
> **OSW는 [AutumnColor77/Live-MR-Manager](https://github.com/AutumnColor77/Live-MR-Manager)에서 갈라져 나온 별개의 앱입니다.** 원본의 모드(개조판)가 아니라 독자적으로 유지·발전하는 프로젝트입니다.
>
> - 아이디어와 초기 구조를 원본에서 가져왔고, 그 뒤 오디오 엔진·정렬 로직·UI를 전면 재작성했습니다. 초기 설계·구현의 저작권은 원 개발자에게 있으며 MIT 조건에 따라 저작권 표시를 [`LICENSE`](LICENSE)에 함께 싣습니다.
> - **설치·데이터·업데이트가 전부 분리되어 있습니다.** 앱 식별자가 `com.osw.desktop`이라 원본과 나란히 설치되며, 업데이트도 이 레포의 릴리즈만 봅니다. (원본 사용자는 첫 실행 때 데이터를 가져올지 물어봅니다.)
> - 원본에 대한 문의·이슈는 원본 레포로, OSW에 대한 것은 [이곳](https://github.com/Temmis2077/OSW/issues)으로 부탁드립니다.

## ✨ 주요 기능

### 🤖 AI 가사 자동 정렬
- **CTC 강제정렬 엔진**(Rust + ONNX Runtime): wav2vec2 모델로 가사 줄별 타임스탬프 자동 배치, 분리된 **보컬 스템 우선** 사용.
- **정렬 언어**: 한국어 / English / **랩·혼합(한+영)** — 랩 모드는 두 모델을 돌려 줄마다 우세 언어 채택.
- **앵커 제약 정렬** — 수동으로 맞춘 줄·보컬시작 마커를 하드 앵커로 삼아 구간별로 정렬한다. 한 번의 밀림이 곡 전체로 전파되지 않고, 사용자가 고친 줄이 다음 정렬의 기준이 되어 곡마다 정확해진다.
- **줄별 신뢰도 표시** — 음향 확신도가 낮은 줄을 편집기에서 "확인" 배지로 강조해, 그 줄만 검토·수정하면 되게 한다.
- **정렬 전용 디리버브** — 리버브·이펙트가 심하면 정확도가 떨어져서, 분리된 보컬의 잔향을 걷어낸 드라이 보컬로 정렬한다(정렬할 때만 실행·캐시, **재생엔 미적용**) → [docs/DEREVERB.md](docs/DEREVERB.md).
- **괄호 코러스 보존** — `사랑해 (사랑해)`처럼 실제로 불리는 코러스를 정렬 대상에 유지(곡 구조 지시어 `[Chorus]`만 제거).
- 정렬 모델 인앱 다운로드, 정렬 대기열(복원 지원), 길이 타당성 보정.

### 🔎 노래 추가 통합 검색
- 유튜브 + 가사 사이트를 한 번에 검색, **공식 음원 우선 추천**("Provided to YouTube by …" / "Auto-generated by YouTube" 가중).
- 드래그·드롭 다중 추가, 제목/가수 자동 추정, 곡 정보·장르·카테고리 등록.

### ⚡ MR 분리 GPU 가속
- **선택 설치형 GPU 가속 팩(TensorRT)** — NVIDIA GPU에서 무거운 RoFormer 분리를 **곡당 ~30초**로. 앱 설정에서 **다운로드 버튼 한 번**으로 받아 설치(없으면 기존대로 CPU/DirectML로 동작).
- 실측·원인 분석은 아래 [MR 분리 성능](#-mr-분리-성능--실측-분석), 구조는 [docs/GPU_ACCELERATION.md](docs/GPU_ACCELERATION.md).

### 🧩 커스텀 분리 모델
- `설정 → AI 엔진 → 커스텀 모델`에 **가이드 + 추천 모델 원클릭 추가** 카탈로그. 프리셋(아키텍처)이 맞춰져 있어 실패하지 않음.
- 직접 받은 ONNX도 프리셋 지정 후 추가 가능 → [docs/CUSTOM_MODELS.md](docs/CUSTOM_MODELS.md).

### 🗂️ 라이브러리 관리
- **장르**(사운드) 와 **카테고리**(씬/시장)를 분리한 2축 표준 분류, 기존 데이터 자동 재매핑.
- MR 분리·AI 정렬 대기열을 저장·복원(앱/PC 재시작 후 이어서 처리), 유튜브 실패 시 지수 백오프 재시도.
- CSV 가져오기/내보내기, JSON 백업·복원·자동 복구.

### 🔊 오디오 엔진
**지금 쓸 수 있는 것**
- **실시간 출력 장치 전환** — 재생 중에도 즉시 전환(위치·볼륨·피치/템포 유지), 선택 저장. 가상 케이블(VoiceMeeter/OBS)로 보내 방송에 활용.
- **출력 리미터** — 여러 소스를 합칠 때의 클리핑 방지(기본 켜짐).

**엔진은 완성됐고 UI 준비 중** — 아래는 백엔드가 동작하며 안전한 기본값으로 켜져 있지만, 제대로 된 믹서 화면을 설계 중이라 조작 UI는 아직 노출하지 않았습니다.
- **모니터 / MR 이중 채널** — 채널마다 다른 출력 장치, 채널×소스(보컬·인스트·메트로놈) 2×3 라우팅 매트릭스.
- **트랙 믹서**(독립 페이더·음소거·솔로), **메트로놈**(BPM 클릭·탭 템포), **버스별 지연 보정**.

### 📝 가사 싱크 편집기 & 오버레이
- 3줄(원문/차음/번역) 가사, 보컬 시작·간주 마커, 인트로 자동 건너뛰기.
- 인앱 가사 호버창(크기·투명도 조절), OBS 오버레이(폰트 크기·키/BPM 표시).

## 📊 MR 분리 성능 — 실측 분석

RoFormer 계열(RawWaveform) 모델로 대량 분리 시 **곡당 20~30분, 58곡에 12시간+**가 걸리던
문제를 실측으로 추적해 잡았습니다. "ONNX라서 느리다"는 전제부터 틀렸습니다 — 같은 런타임에서
MDX/Kim Vocal 2 + DirectML은 곡당 18.5초였습니다.

### 원인 (3겹)
1. `ort` 빌드 피처에 `cuda`가 빠져 GPU EP 등록이 실패.
2. **ORT는 EP 등록 실패를 경고만 남기고 CPU로 계속 진행** → 로그엔 `Using: GPU (CUDA)`라 찍히며 실제로는 CPU로 도는 상태가 오래 은폐됨.
3. CUDA를 제대로 붙여도 CPU보다 느림 — 이 그래프는 **노드 5118개가 거의 융합되지 않아** 연산이 아니라 **커널 실행 오버헤드**에 묶임(GPU 사용률 7%, 노드 실행 시간 합 5.0s vs 실제 19.3s).

→ 런타임이 아니라 **그래프 융합**이 병목. 그래서 **TensorRT**(그래프 융합).

### 실측 (RTX 2070 8GB · Mel-Band RoFormer Deux · 입력 `[1,2,352800]` 정적 · 8초 청크)

| 경로 | 청크당 | 3분30초 곡 | 58곡 |
| :--- | ---: | ---: | ---: |
| 기존 (CPU + GraphOpt Level1) | ~39,000 ms | 20~30분 | **12시간+** |
| CPU (Level3) | 14,113 ms | 8.2분 | ~8시간 |
| CUDA (cuDNN 존재) | 18,200 ms | 10.6분 | 더 느림 |
| DirectML | 크래시 `887A0006` (TDR) | — | — |
| **TensorRT (GPU 가속 팩)** | **~850 ms** | **~30초** | **~29분** |

- **정확도**: CPU vs TensorRT 출력이 소수점 8자리까지 동일(샘플 141만 개). 품질 저하 없음.
- **엔진 캐시**: TensorRT 엔진은 GPU 아키텍처별(RTX 2070=`sm75`)로 첫 빌드 ~150초, 이후 캐시 적중 시 로드 12~17초.
- **함정**: ORT는 provider DLL을 제한된 검색 플래그로 열어 **PATH로는 의존 DLL을 못 찾음**(`Error 126`). Win32 `LoadLibraryExW`로 **절대경로 선적재**해 해결.

> GPU 가속 팩(cuDNN/TensorRT DLL, 압축 ~2.6GB)의 NVIDIA 런타임 `.dll`은 표준 SLA/EULA
> (TensorRT §8.2, cuDNN, CUDA Attachment A)가 재배포를 허용하며, 조건(고지)은 설치 시
> `NVIDIA-NOTICE.txt`로 충족합니다.

## 🎯 방향 — 개방형 미니 DAW

- **스템이 중심**: 보컬·MR을 넘어 **악기별 분리**를 더해, 곡을 완전히 열어 다룬다.
- **분리 → 재조합**: 채널 이펙트(MR 리버브 등)·마이크 입력·내부 라우팅·VST 호스트를 얹어 작은 DAW로.
- **스트리머 우선, 범용 지향**: 노래 방송이 주 대상이되 혼자 연습·커버 제작·악기 연습에도.
- **개방**: 로컬 구동, 자체 릴리즈·자체 업데이트, 특정 서비스에 종속되지 않는 기본 기능 완결.

## 🏃 개발 환경

### 사전 요구
- **Windows 10/11** (릴리스·개발 타깃 Windows 전용)
- [Rust](https://www.rust-lang.org/tools/install) (rustup + stable)
- [Node.js](https://nodejs.org/) (LTS, v18+)
- [LLVM](https://releases.llvm.org/) / `winget install LLVM.LLVM` — `signalsmith-stretch` 빌드에 **libclang** 필요(`LIBCLANG_PATH` → `...\LLVM\bin`)
- [C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/) — **「C++를 사용한 데스크톱 개발」** 워크로드

### 시작
```bash
npm install            # 의존성
npm run tauri dev      # 개발 모드
npx vitest run         # 프론트 테스트
cd src-tauri && cargo test --lib   # Rust 테스트
```

**Windows PowerShell 참고**
- `npm` 미인식 시 터미널 재시작 또는 `npm.cmd`
- 실행 정책 오류 시 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
- 캐시/데이터: `%LOCALAPPDATA%\com.osw.desktop\`, 관리형 도구: `%LOCALAPPDATA%\LiveMRManager\tools\`
  (구 버전 데이터는 `com.autumncolor77.live-mr-manager\`에 있었고, 첫 실행 시 새 위치로 가져올지 물어봅니다. 관리형 도구 폴더는 식별자와 무관해 그대로 유지됩니다.)
